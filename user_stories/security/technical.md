# Security — Technical
_Every security mechanism of the app. Today: Firebase App Check (genuine-app protection) for the Android and iOS apps — providers, startup order, console and store setup, and what is left before enforcement._

## How it works
**App Check (genuine-app protection).** At startup, `AppInitialization.init()` runs three tasks in parallel: SharedPreferences, localization and a private Firebase step. The Firebase step calls `Firebase.initializeApp` and then, immediately, `AppCheckManager.init()`, so no Firebase call can run before App Check is active. `AppCheckManager` activates Firebase App Check on Android and iOS only. Release and profile builds use **Play Integrity** (Android) and **App Attest** (iOS); debug builds (`kDebugMode`) use the **debug providers**. From then on the SDK attaches an App Check token to every request to a protected Firebase product, and refreshes it on its own before it expires. The token time-to-live is 12 hours, set in the console. Web, macOS and Windows skip activation.

## Key components
- `AppCheckManager` (`lib/data/firebase/managers/app_check_manager.dart`) — the one place App Check is configured; static `init()`.
- `AppInitialization` (`lib/app/app_initialization.dart`) — chains `AppCheckManager.init()` right after `Firebase.initializeApp`.
- `LoggerManager` (`lib/core/managers/logger_manager.dart`) — the central logger (created with this feature); logs an activation failure. Logs show in debug builds only.
- `ios/Runner/Runner.entitlements` — `com.apple.developer.devicecheck.appattest-environment` = `production`, wired through `CODE_SIGN_ENTITLEMENTS` on the Runner Debug, Release and Profile configurations.
- Android release signing in `android/app/build.gradle.kts` — reads `android/key.properties` (git-ignored), which points to the upload keystore shared with sweetgathering. Without that file, release builds fall back to the debug keys.

## Important flows
1. Cold start: binding → portrait lock → `Future.wait` [prefs, localization, Firebase step].
2. Firebase step: `Firebase.initializeApp` → `AppCheckManager.init()`.
3. `init()`:
   - an unsupported platform returns at once;
   - otherwise `activate` runs with the providers chosen by `kDebugMode`;
   - an exception is logged and the app continues.
4. On the first request to a protected product, the SDK gets a token from the provider and attaches it.
5. On a debug build's first run, the debug token is printed:
   - Android: Logcat, `DebugAppCheckProvider`;
   - iOS: Xcode console, with the `-FIRDebugEnabled` launch argument.

   The owner adds it under App Check → Apps → ⋮ → Manage debug tokens.

## Edge cases & failure handling
- **Activation error:** it is logged and the app still starts. Once enforced, that device's requests are refused.
- **Activation must come first.** Before `activate`, Android has no provider and Apple defaults to DeviceCheck, which is not configured. The package default for Apple is also DeviceCheck, so the providers are passed explicitly.
- **Play Integrity fails on sideloaded release builds and on emulators.** Test with debug builds and a registered debug token.
- **App Attest does not work in the simulator.** Debug builds use the debug provider.
- **About one Android check in six failed on-device** in sweetgathering (measured 2026-11-06). Its fix is a shared "refresh the token once, then retry once" helper (`AppCheckRecovery`). Zakio does not have it yet because nothing calls Auth or callables. Add it in `AppCheckManager` with the first feature that does.

## Security & permissions
- **Enforcement is OFF for every product** — today that is only the Realtime Database.
- Enforce in App Check → APIs only after the metrics show mostly verified requests. It takes up to 15 minutes, and from then on every unverified request is refused.
- When Firestore or SQL Connect are added, enforce them the same way. Remote Config and Hosting are not covered by App Check.
- Debug tokens are secrets: never commit them or put them in code.
- `key.properties` and the keystore are never committed.

## Platform notes
- **Android:** Play Integrity in release, the debug provider in debug.
- **iOS:** App Attest, environment `production`; debug provider in debug. The app minimum was raised from iOS 13.0 to **15.0** (Runner target, all three configs) — Firebase's iOS packages (core, database, app-check) require 15.0, so the iOS build failed at 13.0. Matches sweetgathering. The Podfile still says 16.0 (pre-existing, unchanged).
- **Web:** not activated. The web is an information landing page only, with no Firebase data access.
- **macOS / Windows:** not activated (not shipped). The plugin's Windows support is debug-only.
